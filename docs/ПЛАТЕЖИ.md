# Платёжный модуль

Папка lib/payments. Не зависит от магазина: чтобы поставить в другой сайт, нужны lib/payments, lib/payment-service.js, lib/secrets.js и три таблицы в базе (заказ, платёж, начисления). В шаблон магазина из acegram модуль ещё не перенесён (acegram не менялся).

## Как владелец подключает оплату
Админка → Оплата. Вводит ключи из кабинета банка, ставит галочку «Включить», нажимает «Проверить подключение». Копирует показанный адрес уведомлений в кабинет банка. Выключает тестовый режим. Править файлы не нужно.

## Что внутри
- Один интерфейс у всех провайдеров: init (создать платёж), webhook (проверить и разобрать уведомление), refund, check.
- Заказ считается оплаченным только после подтверждённого уведомления: подпись (Робокасса, Т-Банк, CloudPayments) или запрос статуса платежа в API (ЮKassa). Сумма в уведомлении должна совпасть с суммой заказа.
- Повторные уведомления не дублируют оплату и начисления. Начисления партнёрам создаёт только отметка «оплачен», то есть только с оплаченных заказов.
- Возврат в админке: ЮKassa, Т-Банк и CloudPayments возвращают деньги через API, у Робокассы возврат делается в её кабинете, затем записывается на сайте. Начисления пересчитываются по доле возврата. Возврат, сделанный в кабинете банка, приходит уведомлением и тоже записывается.
- Ключи шифруются в базе (AES-256-GCM, ключ в config.json), в админке видны только 4 последних символа. Ключи можно задать переменными окружения (YOOKASSA_SHOP_ID, YOOKASSA_SECRET_KEY, ROBOKASSA_LOGIN и др., список в lib/payments/index.js).
- Чеки: режим «не передавать» (самозанятый сам формирует чек в «Мой налог») или «передавать провайдеру» (облачная касса, 54-ФЗ). Налогообложение и НДС выбираются в админке.
- Тестовый режим: провайдер «Тестовая оплата» без денег. При выключении недоступен.

## Что сверено с документацией (04.11.2026)
- ЮKassa: проверены создание платежа (POST /v3/payments, Basic, Idempotence-Key, confirmation redirect, receipt, metadata), СБП (payment_method_data type sbp), уведомления (без подписи, проверка запросом статуса), возврат (POST /v3/refunds). Не проверено по документации: коды системы налогообложения и ставки НДС в receipt (tax_system_code 1–6, vat_code 1–4, взяты по памяти), эндпоинт проверки ключей GET /v3/payments?limit=1.
- Робокасса: проверены адрес формы, формулы подписи (с Receipt и Shp), ResultURL с Паролем №2, ответ OK{InvId}, тестовый режим, структура Receipt. Документация противоречива по кодированию Receipt в подписи: реализовано URL-кодирование, как в их примерах. Проверить тестовым платежом.
- Т-Банк и CloudPayments: документацию автоматически прочитать не удалось (Т-Банк закрыл страницы для роботов, у CloudPayments нужные разделы не загрузились). Алгоритм Token Т-Банка, подпись HMAC CloudPayments, адреса методов, поля чеков реализованы по памяти. Провайдеры помечены «бета» и включаются только отдельной галочкой. Обязательно сверить с документацией и пройти тестовый платёж.
- СБП: работает через ЮKassa. Отдельный СБП Т-Банка, Сбер, ВТБ и другие банки не реализованы.

## Что нельзя проверить без кабинетов и ключей
Реальное создание платежей и приём уведомлений, подпись Робокассы с боевыми паролями, требования банков к магазину, работу чеков (нужна подключённая касса и верные налоговые настройки), список IP-адресов провайдеров (проверка по IP не включена, защита держится на подписи и запросе статуса).

## Не реализовано
Сбер, ВТБ, Альфа, Точка, ЮMoney как отдельные провайдеры; двухстадийные платежи; рекуррентные списания; частичная оплата заказа; чеки возврата (формируются в кабинете провайдера или кассе); выплаты партнёрам через сервис (остаются ручными).
